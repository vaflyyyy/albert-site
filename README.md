# Albert Ermekov — сайт бариста и кофейного консультанта

Next.js 15 (App Router) + TypeScript + Tailwind CSS. Интерфейс на русском. Тёмный «эспрессо»-дизайн, цены в тенге (₸),
запись с подтверждением через Telegram и страницей статуса для клиента.

> **Статус проверки.** Логика бэкенда (БД, статусы, двойная запись, авторизация Telegram, скрытие личных данных, откат при сбое доставки)
> проверена скриптом на тестовой SQLite-базе с подменой Telegram API — все проверки пройдены. `npm install`, `npm run lint`,
> `npm run typecheck` и `npm run build` в среде разработки запустить не удалось (нет доступа к npm) — выполните их у себя первым делом.

## Запуск

Требуется **Node.js 22.13+** (используется встроенный `node:sqlite`, внешних нативных пакетов нет).

```bash
npm install
cp .env.example .env.local     # заполните значения (см. ниже)
npm run dev                    # http://localhost:3000
npm run lint && npm run typecheck && npm run build
```

## Как устроена запись

1. Клиент заполняет форму (имя, телефон, услуга, дата, свободное время, связь, комментарий). Занятые слоты на выбранную дату отключены.
2. `POST /api/bookings`: валидация на сервере → лимит запросов → в **одной транзакции SQLite** проверка слота и сохранение со статусом `pending`.
3. Альберту в Telegram приходит сообщение с кнопками **Подтвердить / Отклонить / Предложить другое время**.
   Если Telegram не принял сообщение, запись удаляется, а клиент видит ошибку (ложного «успеха» нет).
4. Клиент получает **номер записи** (`AE-XXXXXXXX`) и **приватную ссылку** `/booking/<токен>`. Токен — 32 случайных байта; в БД хранится только его SHA-256.
5. Нажатия кнопок приходят на `POST /api/telegram/webhook`: проверяется секрет вебхука, затем Telegram-ID нажавшего (только из `TELEGRAM_ADMIN_IDS`) и чат.
   Статус меняется в транзакции; сообщение в Telegram обновляется; на кнопку всегда есть ответ (`answerCallbackQuery`).
6. Страница статуса опрашивает `GET /api/bookings/status/<токен>` каждые 5 секунд (пока вкладка видна, при ошибках интервал растёт) и показывает статус по-русски и следующие шаги.
   Клиент может отменить запись на этой странице.

Статусы: `pending` Ожидает подтверждения · `confirmed` Запись подтверждена · `rejected` Запись отклонена ·
`reschedule_requested` Предложено другое время · `cancelled` Запись отменена.

«Предложить другое время»: статус становится `reschedule_requested`, бот просит ответить на сообщение текстом (до 300 символов) —
этот текст клиент увидит на странице статуса.

**Двойное бронирование.** Подтверждённой записи на слот может быть только одна: проверка внутри транзакции + уникальный частичный индекс
`(requested_date, requested_time) WHERE status='confirmed'`. Заявки (`pending`) могут пересекаться — Альберт выбирает, какую подтвердить;
вторую подтвердить нельзя (кнопка ответит «время занято»).

Публичные endpoint'ы **не отдают** телефон и комментарий клиента.

## Настройка Telegram (кнопки)

Подробно: **docs/TELEGRAM-SETUP.md**. Коротко:

1. Бот в @BotFather → `TELEGRAM_BOT_TOKEN`; напишите боту `/start`; ваш ID и chat id покажет команда `/id` → `TELEGRAM_CHAT_ID`, `TELEGRAM_ADMIN_IDS`.
2. Придумайте `TELEGRAM_WEBHOOK_SECRET` (`openssl rand -hex 24`).
3. **Локально:** `npm run dev`, во втором окне `npm run telegram:poll` — кнопки работают без публичного адреса.
4. **Продакшен:** задайте `NEXT_PUBLIC_SITE_URL=https://ваш-домен`, затем `npm run telegram:webhook -- set` (проверка: `-- info`).
5. Проверка связи с ботом: `npm run telegram:test`.

## База данных и миграции

SQLite-файл `./data/bookings.sqlite` (или `DATABASE_PATH`). Таблицы создаются автоматически при первом запросе
(`src/server/db.ts`, версия схемы в `PRAGMA user_version`; новые миграции добавляйте в массив `MIGRATIONS`).

Таблица `bookings`: `id, public_status_token_hash, customer_name, customer_phone, service_id, requested_date, requested_time, comment,
contact_channel, status, owner_note, telegram_chat_id, telegram_message_id, prompt_message_id, created_at, updated_at`.
Также `booking_events` (журнал действий: Telegram-ID администратора, без персональных данных клиентов) и `rate_limits`.

⚠️ SQLite — это файл на диске. Нужен хостинг с **постоянным диском** (VPS, Docker volume, Fly.io/Railway volume). На Vercel/serverless файловая система
временная — там понадобится внешняя БД (Postgres/Turso): реализация изолирована в `src/server/booking/store.ts` и `src/server/db.ts`.
Делайте резервную копию файла `data/`.

## Что редактировать

| Что | Где |
|---|---|
| **Цены (₸)**, длительность, примечания | `src/config/pricing.ts` — единственное место |
| Тексты, услуги, места работы, FAQ, этапы открытия бара | `src/content/ru.ts` |
| Расписание (дни, слоты, горизонт записи) | `src/config/site.ts` |
| Контакты (WhatsApp, Telegram, телефон, Instagram) | `.env.local` → `NEXT_PUBLIC_*` |
| Палитра и шрифты | `tailwind.config.ts`, `src/app/layout.tsx` |
| Фото | `public/images/` — имена файлов в `src/config/images.ts` |

**Цены.** Реальные цены не придуманы: у всех услуг `priceKzt: null`, поэтому показывается «Стоимость уточняется», а для открытия кофейни — «Индивидуальный расчёт».
Чтобы задать цену: `priceKzt: 25000` (и `from: true` для «от 25 000 ₸»). Длительность (`duration`) показывается, только если заполнена.

**Фото.** Просто положите файлы в `public/images/` — они подхватятся сами (`hero.jpg`, `albert.jpg`, `about.jpg`, `bar.jpg`, `service-<id>.jpg`, `portfolio-1.jpg … portfolio-8.jpg`).
Пока файла нет, показывается тёмная заглушка. Стоковые фото не подписываются как фото Альберта; `albert.jpg` — только настоящий портрет.
После добавления фото в production пересоберите проект.

## Безопасность

- Токен бота и секреты — только на сервере (`import "server-only"`), в браузер не попадают.
- Вебхук без `TELEGRAM_WEBHOOK_SECRET` отвечает 503 и ничего не принимает; с неверным секретом — 401 (сравнение за постоянное время).
- Кнопки: только `TELEGRAM_ADMIN_IDS` и только из `TELEGRAM_CHAT_ID`; остальным — «нет прав» и запись в лог (только числовой ID).
- Лимиты запросов хранятся в БД (IP обезличен хешем): запись — 5/10 мин, статус — 600/10 мин, отмена — 10/10 мин.
- В логи не попадают имена, телефоны, комментарии и токены.
- Сообщения для Telegram экранируются (HTML), SQL — только с параметрами.
- Страница статуса: `noindex`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`.

## Казахский и английский

Весь текст лежит в `src/content/ru.ts` по типу `Content` (`src/content/types.ts`). Добавьте `kk.ts` и `en.ts` с тем же типом и подключите
маршрутизацию по языку (сегмент `[locale]` или `next-intl`), заменив `content` из `src/content/index.ts` на выбор по локали.
Тексты ошибок валидации сейчас в `src/lib/booking.ts` — вынесите их в словарь вместе с остальными.
